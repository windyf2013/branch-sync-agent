# Proposal: redesign-web-task-center

## 变更名称

`redesign-web-task-center` — V2 Web 平台信息架构重构（任务中心 + 新建同步）

## 背景

V2 平台（add-web-maintenance-workbench）已交付：认证、工作台首页、历史/详情、任务 runner、推送四道闸、审计、备份等。但工作台信息架构存在缺陷：

- "快速操作"与"周期记录"边界模糊，动作入口分散（推送挂待办区、改判定在 API、快速操作混进度显示）。
- 失败/需人工干预任务无在线处理手段（只能离线 SSH），"保留现场续跑"失去意义。
- 手动同步任务无统一展示与后续动作归属。

本变更重构平台信息架构：**B 区（新建同步）纯发起，A 区（任务中心）唯一状态与处理端**，并为失败现场提供受限 WebSSH 在线处理。

## 目标与成功标准

1. B 区 = 引导式同步发起（源分支 → 勾选 commit → 目标分支），用户手动=人工审核通过、无需四态决策；发起后自动刷新进 A 区。
2. A 区 = 任务中心：自动（Agent cron）与手动两个区块，任务按分支粒度，点击任务进详情页承载全部操作（现场证据 / WebSSH / 重跑 / 推送 / 放弃·恢复 / 人工项处理）。
3. 失败/需人工干预任务在 A 区详情页提供受限 WebSSH 在线处理（仅该 worktree、禁 sudo/禁出目录、复用鉴权、审计）。
4. 推送对任何 SUCCESS 现场开放（自动+手动）；放弃/恢复持久化并与任务列表联动。
5. 保留"保留现场续跑"语义（SSH 处理后 resume 验证→patch）。

## 核心需求

### B 区 · 新建同步（纯发起）

- 源分支 select（branch.md RCIOS 列表）→ 平台经 `bsa commits <src>` 加载候选 commit 列表（sha + 提交说明 + 时间）→ 用户多选勾选 → 目标分支 select → 发起。
- 用户手动发起 = 人工审核通过，无需四态结论判定，直接同步。
- 发起后：web 等待后台"发起成功"反馈，自动刷新，任务进入 A 区手动区块。

### A 区 · 任务中心（唯一状态与处理端）

- 自动区块：Agent cron 周期产生的分支任务（周期=批量，按分支粒度展开；运行中周期 = 各分支任务"进行中"）。
- 手动区块：用户发起的分支任务。
- 展示为分支任务面板列表；所有操作在点击任务后的详情页：
  - 查看现场证据（patch / diff / 编译日志 / Agent 修复记录 / 冲突现场）。
  - WebSSH 窗口（仅失败/需人工干预任务）。
  - 重跑：瞬态失败直接重跑；SSH 处理后保留现场续跑（resume 验证→更新 patch）。
  - 推送（SUCCESS，四道闸：状态/现场存在/非 forbidden_branches/现场干净）。
  - 放弃 / 恢复（持久化，任务列表/待办联动过滤）。
  - 人工项处理（改判定 / 确认继续）。

### WebSSH（受限终端）

- 仅该任务 worktree 目录；禁 sudo、禁出目录。
- 仅"失败/需人工干预"的必要任务开放。
- 复用平台登录鉴权；终端操作记审计。

## 设计方向（已定决策）

1. **B/A 分离**：B 只做"发起前的选择操作"；一切任务状态、结果、后续动作在 A 区。周期仅指 Agent 自动 cron 来源。
2. **任务粒度 = 分支级**：自动周期展开为多个分支任务，与手动任务统一模型。
3. **推送归属**：对任何 SUCCESS 现场开放，键在任务详情页。
4. **重跑语义**：瞬态失败直接重跑；需人工 → WebSSH 在线处理 → 保留现场续跑（`bsa rerun` 保留模式）。
5. **放弃/恢复**：平台本地状态表（分支/commit 粒度），A 区任务列表过滤已放弃项，可恢复。
6. **commit 列表数据源**：V1 新增只读 CLI `bsa commits <src>`（git log / 检测窗口），平台子进程调用；仅返回 sha + message + 时间。
7. **超期即弃保持**：worktree 仅保留当前周期，V1 cron 清理。
8. **数据/写路径边界保持**：读经投影/CLI，写经 V1 CLI 子进程；审计 append-only；WebSSH 操作同样审计。

## 边界（本变更不做）

- 不提供平台内文件编辑器（WebSSH 终端替代，文件编辑在终端内）。
- 不做审批链、多仓库管理。
- 不做自动推送、不做 `--force`（推送硬约束保持）。
- 不改变 V1 周期检测/决策/同步核心行为（仅新增 `bsa commits <src>` 只读命令）。

## V1 改动清单

| 类别 | 改动 |
|---|---|
| CLI | 新增只读 `bsa commits <src>`（返回候选 commit：sha/message/time） |
| 保持 | `bsa rerun` 保留现场/`--fresh` 两种模式；四道闸；超期即弃 |

## 平台改动清单（重构为主，WebSSH 为新项）

| 类别 | 改动 |
|---|---|
| B 区 | 三步引导表单（源分支→commit 多选→目标分支），commit 异步加载；发起后自动刷新进 A |
| A 区 | 重构为任务中心：自动/手动分区、分支任务面板、任务详情页聚合全部操作 |
| WebSSH | 受限终端（映射 worktree、禁 sudo/出目录、复用鉴权、审计）；最大新项，独立评审 |
| 推送 | 对任何 SUCCESS 现场开放（自动+手动），键在任务详情页 |
| 放弃/恢复 | 平台本地状态表 + 任务列表联动过滤 |
| 联动 | B→A 自动衔接；放弃过滤；手动 SUCCESS 推送 |

## grill-me 决策记录

### G1 WebSSH 沙箱强度与威胁模型（2026-08-25）

- **问题**：WebSSH"禁出目录/禁 sudo"如何从技术上强制？普通 bash 无法防 `cd /` 逃逸，禁 sudo 依赖部署层。
- **用户回答**：同意三层防御；并补充部署约束——平台运行账号为非维护类超管、无 sudo 密码权限（sudo 天然不可用）。
- **结论**：
  - 威胁模型 = 受信任内部用户（能登录平台者可信），WebSSH 防误操作/越权到其他 worktree/读无关文件，不防恶意逃逸。
  - 三层防御：①受限入口 `cd <worktree> && exec bash` ②部署层平台账号无 sudo 密码权限、shell 启动清 PATH 中 sudo ③审计 + 会话记录（脱敏）。
  - 不引入 bwrap/nsjail/docker 强沙箱（内部工具过度）。

### G2 候选 commit 范围（2026-08-25）

- **问题**：`bsa commits <src>` 返回哪些 commit？
- **用户回答**：最近 N 条平铺。
- **结论**：返回源分支最近 N 条（默认 50，可配），sha + message + time，不做已同步/已包含过滤；用户勾选即信任，已包含 commit 同步时 EMPTY 跳过并在结果体现。

### G3 任务中心范围（2026-08-25）

- **问题**：任务中心列出哪些任务？全量会膨胀，历史页已承担完整历史。
- **用户回答**：只列一个周期内的所有任务，包括 agent cron + 用户手动。
- **结论**：A 区任务中心 = 最近一个周期窗口内的所有分支任务（自动 + 手动，分支粒度）；超出窗口的任务收敛进历史报告页/操作日志。

### G4 WebSSH 开放范围（2026-08-25）

- **问题**：WebSSH 对哪些任务开放？"失败/需人工干预"需精确。
- **用户回答**：好（采纳推荐）。
- **结论**：SSH 仅开放给"有 worktree 现场且执行失败/停批"的分支任务（FAILED/PARTIAL/MANUAL 且有 worktree_path）；ManualReview 待确认项走人工项处理（改判定/确认继续），不开 SSH。

### G5 终端审计粒度（2026-08-25）

- **问题**：WebSSH 操作审计记到什么粒度？每条命令可能含密钥等敏感内容。
- **用户回答**：可以（采纳推荐）。
- **结论**：会话级必记（谁/何时/哪个 worktree/时长）+ 命令脱敏记录（过滤明显的密码/密钥行）；命令审计粒度可配。

### G6 WebSSH 组件选型与免认证（2026-08-25）

- **问题**：WebSSH 组件选型（ttyd vs 自研）；终端是否需二次认证。
- **用户回答**：选 ttyd；web 访问终端**免认证**（复用平台登录会话，不二次登录）。
- **结论**：
  - 选型 **ttyd**（单 C 二进制，简单稳定；自研 xterm.js+pty 不推荐）。
  - 每会话一个 ttyd 实例：`ttyd -o -p 0 -W -i 127.0.0.1 -- timeout 1800 bash -c "cd <worktree> && exec bash"`（`-o` 断开即退出、入口硬编码 worktree、空闲上限 30min、绑 127.0.0.1）。
  - 平台反代 `/ssh/ws/<token>` 到 ttyd 端口，复用登录会话（免二次认证）。
  - 审计：会话级必记（平台审计表）；命令级可选 ttyd `-l` 原始终端日志本地受限落盘（不做可靠脱敏，不进平台日志/审计 UI）。
